# ResearchAgent 独立项目设计

## 目标与用户授权

用户选择以 Future-House/paper-qa 为原型的独立项目，并授权开发、测试后上传到私有仓库 https://github.com/WannaSaveWorld/ResearchAgent 。不复制简历、成绩单、照片及其他个人工作区资料。当前远端只有 README，默认分支 main。

目标是一个可以在本地启动、解释源码、复现评测的科研文献助手。它应支持实验室组会和课题调研中的文献上传、检索、问答及引用核查。实现完成不代表证明了历史部署、历史使用人数或简历时间线。

## 方案比较与选择

1. Fork 整个 PaperQA：保留完整上游结构，但代码与依赖范围大，不利于突出新增部分。
2. 独立项目依赖 PaperQA：明确复用与新增边界，模块较少，方便学习与测试。用户已选择此方案。

Python 3.11+，以可验证的依赖版本为准；复用 PaperQA 的 Doc/Text、证据提取和回答流程，不声称 PaperQA 原生使用 FAISS 或 LangGraph。以适配层隔离上游 API，避免 monkey patch。

## 功能与架构

### 1. 文献入库与来源

- 接收 PDF 上传，生成内容哈希 ID，重复上传返回同一文档；限制大小和页数，防止文件名路径穿越。
- 逐页解析可提取文本的 PDF，识别常见章节标题，并按段落与长度切分。每个片段保存文档 ID、标题/章节、文件页序、可选印刷页标签、原文及稳定片段 ID。
- 首版不宣称能完美理解任意双栏或扫描 PDF；无可提取文本时返回明确的 OCR 提示，不静默成功。跨页段落可保持按页切分以确保溯源准确。
- SQLite 保存文档、片段及会话。上传文件与索引落在运行目录，默认不提交 Git。

### 2. 混合检索

- BM25 与 FAISS 两路召回，RRF 融合，以稳定片段 ID 去重。单路排名缺失不会报错，限制候选与最终 top-k。
- 中文采用一致分词策略，英文保留科研缩写；查询与文档使用相同处理。
- 使用真正的语义 embedding 接口，默认配置可兼容标准 embeddings API，也提供可选本地 embedding。缺少 embedding 配置时明确失败，不把随机向量或哈希当作语义检索。
- 索引记录 embedding 模型、向量维度和语料版本；模型变更需要重建，不能混用不同向量空间。持久化加载后需维持片段映射。

### 3. PaperQA 适配

- 将检索到的候选转为 PaperQA Doc/Text，并保留外部片段 ID 到来源的映射。
- 在兼容设置下使用 PaperQA 的证据筛选/摘要与问答能力，关闭其重复候选召回或通过适配接口注入候选，保证回答确实使用本项目混合检索的证据。
- 禁止仅声明依赖却绕过 PaperQA；集成测试应验证候选进入 PaperQA、引用能回到原片段。上游 API 如不兼容，固定经过测试的版本并记录调整。
- 回答引用只允许映射到实际候选，页码来自解析元数据。引用 ID 有效不代表论断已被逻辑证实，界面提供原文核查。
- 证据不足时允许拒答，不凭空生成来源。保留上游来源和许可证说明，不删除必要声明。

### 4. LangGraph 工作流

- 查询处理 → 本地混合检索 → 必要时外部论文搜索 → PaperQA 证据与回答 → 引用校验 → 返回。
- 使用状态记录问题、检索结果、来源、工具调用与错误。用户必须显式开启外部检索，默认只查本地。
- 外部检索通过可配置 MCP 服务调用真实工具，配置使用服务地址和工具名；提供 stdio 或 HTTP 的可运行示例，实际支持的传输由 SDK 版本固定。
- 限制工具次数、超时及图执行步数；提供可读错误，不无限重试。文献内容作为数据，不能覆盖系统指令或取得任意工具执行权限。
- 对外部搜索结果标明 URL 来源，不伪装成本地 PDF 页码。

### 5. FastAPI 与操作入口

- 健康检查；上传/列出文档；检索；创建/查询会话；问答；按文档 ID 与文件页序访问来源。
- 文档与会话持久化，重启后可继续使用；默认单用户本地服务，监听 127.0.0.1。首版不作为公开多租户服务。
- 简洁中文页面用于上传、提问、查看证据和引用。API 文档可通过 /docs 操作。
- API 错误区分非法输入、配置缺失、解析失败、模型服务超时及内部异常；响应不返回密钥与完整内部堆栈。

## 配置与运行

提供 .env.example：聊天模型、embedding 模型、服务端点、API key 变量名、数据目录、上传限制、工具限制、MCP 配置。用户自行填入密钥，仓库不包含真实密钥。

无真实模型密钥时，仍运行离线测试、文献解析和使用注入式测试替身的工作流测试；真实模型与外部 MCP 的线上验证必须单独标记，不将模拟结果说成线上成功。测试替身不作为生产回答模式。

提供 Python 安装与启动说明、依赖锁定/约束、演示用自制文献、评测题集、架构图、模块说明和常见问题。

## 验证与验收

1. 解析测试：多页、中文英文、空页、扫描件、章节、重复上传及文件名安全；页码与证据不漂移。
2. 检索测试：BM25/向量/RRF 排名、去重、空语料、模型不匹配、重启持久化；向量单测使用显式测试替身，另行验证真实 embedding 端点。
3. PaperQA 集成：检索候选确实进入证据回答，生成引用可映射；缺包或不兼容返回明确错误。
4. 工作流测试：本地命中、证据不足、外部检索关闭/开启、工具失败、超时、次数限制、会话隔离。
5. API 测试：完整上传到问答与来源查询，超大/非法文件，错误响应与持久化。
6. 评测：同一题集比较 BM25、向量与混合检索的 Recall@k/MRR，并报告配置与题数；只报告实际运行结果，不预填提升百分比。
7. 上传前运行自动化检查、审查密钥和数据文件，提交真实日期与诚实说明；通过 GitHub 连接上传，保留远端已有内容。

## 尚未由用户指定、交给实现者决定

具体默认聊天模型、embedding 提供商、本地模型选项和 UI 组件以兼容性、易运行及成本为依据。若没有用户密钥，不阻止完成代码与离线验收，但如实列出尚未完成的线上验证。

## 非目标

首版不做多用户权限、分布式队列、任意网站爬取、付费文献下载、完整 OCR 平台或对复杂 PDF 排版的完美恢复。不写虚构实验室用户数、准确率、耗时收益或历史开发记录。
